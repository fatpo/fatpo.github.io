梳理后的答案：

```text
一、核心定义
文档（Document）：ES 中最小的数据单元，是可被索引的 JSON 格式数据（类似关系型数据库的 “行”），每个文档有唯一的_id标识。
类型（Type）：早期 ES 中用于对索引内文档分类的逻辑容器（类似关系型数据库的 “表”），ES 7.x 后已被废弃（原因：同一索引下不同类型的 mapping 会导致分片存储冲突，降低查询效率），目前一个索引仅支持一种 “隐含类型”_doc。
索引（Index）：同类文档的集合（类似关系型数据库的 “数据库”），是 ES 中数据存储和检索的顶层单位，包含多个分片，统一管理文档的 mapping（字段定义）、setting（分片数、副本数等）。
分片（Shard）：索引的物理拆分单元，是 ES 分布式存储的核心。每个分片是一个独立的 Lucene 索引，可分散存储在不同节点上，通过分片并行处理查询，突破单节点的存储和性能限制。
副本（Replica）：分片的冗余备份（称为 “副本分片”），对应的原始分片称为 “主分片（Primary Shard）”，副本与主分片不在同一节点。

二、关联关系
层级关系：索引 → （废弃的类型）→ 文档，文档是索引的最小数据单元，索引是文档的聚合容器。
存储关系：索引 = 多个主分片 + 对应副本分片，每个文档通过哈希算法（hash(_id) % 主分片数）路由到唯一主分片，写入时先写主分片，再同步到副本分片；查询时可从主分片或副本分片读取。
集群关系：分片（主 + 副本）分散在集群多个节点上，副本分片不能与对应主分片同节点，保障数据不丢失。

三、副本的核心作用
数据高可用：当主分片所在节点故障时，ES 会通过 “主选举算法（基于多数派投票）” 将对应的副本分片提升为新主分片，避免数据丢失。
提升查询性能：查询请求可分散到主分片和多个副本分片并行处理，增加查询吞吐量（尤其读多写少场景）。
故障恢复支持：节点恢复后，副本可作为数据同步的来源，快速重建主分片或补充其他副本，恢复集群平衡。
```

如果一个索引有3个分片，2个副本，然后一共有6个节点，你可以简单说一下每个物理节点上的数据归属吗?

```text
具体分布逻辑（6 节点场景）
1. 主分片分配：3 个主分片（P0、P1、P2）平均分散在 3 个节点，每个节点仅 1 个主分片（避免单节点承载多个主分片，降低故障影响）。
2. 副本分片分配：每个主分片的 2 个副本（R0-1、R0-2；R1-1、R1-2；R2-1、R2-2），分散到剩余所有节点，优先让每个节点分片数均衡。

其中一种分配逻辑：
节点 1：P0（主分片） + R1-1（P1 的第一个副本）
节点 2：P1（主分片） + R2-1（P2 的第一个副本）
节点 3：P2（主分片） + R0-1（P0 的第一个副本）
节点 4：R0-2（P0 的第二个副本） + R1-2（P1 的第二个副本）
节点 5：R2-2（P2 的第二个副本）
节点 6：（若集群开启自动均衡）可能无分片，或承接某个节点的冗余副本（实际中 6 节点会让前 5 个节点各 1-2 个分片，节点 6 备用）

```

## 1.2 用 REST API 完成：创建一个名为 “product” 的索引，指定分片数 3、副本数 1，同时定义字段（id:keyword、name:text、price:double、create_time:date）。
```text
curl -XPUT "http://127.0.0.1:9200/product?pretty" -H 'Content-Type: application/json' -d'
{
    "settings": {
      "index": {
        "number_of_shards": 3,
        "number_of_replicas": 1
      }
    },
    "mappings": {
      "properties": {
        "id": {
          "type": "keyword"
        },
        "name": {
          "type": "text"
        },
        "price": {
          "type": "double"
        },
        "create_time": {
          "type": "date"
        }
     }
   }
}
'
```
返回值：
```text
{
  "acknowledged" : true,
  "shards_acknowledged" : true,
  "index" : "product"
}
```
